# WB-STD-001 «Идентификаторы MQTT-топиков в экосистеме Wiren Board»

**Версия 1.0. Дата: 2026-07-08.**

> Настоящий документ нормативно развивает правила формирования имён MQTT-топиков, изложенные в публичных соглашениях [Wiren Board MQTT Conventions](https://github.com/wirenboard/conventions), раздел 1.2 «Naming Conventions (2024+)». Стандарт согласован с источником и не противоречит ему.

---

## 1. Область применения

Стандарт устанавливает правила формирования идентификаторов MQTT-топиков, публикуемых в брокере экосистемы Wiren Board.

Под идентификатором понимается компонент топика, расположенный между двумя соседними символами `/`: имя устройства, имя канала, имя метаключа и иные пользовательские компоненты топика.

**Канал** (control в терминологии [Wiren Board MQTT Conventions](https://github.com/wirenboard/conventions)) — элементарная управляемая или отображаемая величина устройства, представленная в MQTT топиком вида `/devices/<device_id>/controls/<channel_id>`. В настоящем стандарте «канал» используется как основной термин; колонка `id` в таблицах канона §6 — это `<channel_id>` соответствующего канала.

Стандарт применяется к программному обеспечению Wiren Board, шаблонам устройств и к стороннему ПО, претендующему на совместимость с экосистемой Wiren Board.

Стандарт не регулирует формат payload, параметры доставки сообщений, политику retained и таксономию топиков — это предмет других документов.

## 2. Формирование идентификаторов

### 2.1 Алфавит

Идентификатор должен состоять только из символов:

- строчные буквы латиницы `a-z`;
- цифры `0-9`;
- символ подчёркивания `_`.

Регулярное выражение алфавита: `[a-z0-9_]`.

В идентификаторе не должны использоваться заглавные буквы, буквы кириллицы и иных алфавитов, знаки препинания, скобки, пробелы, специальные символы и любые символы вне ASCII.

Правило относится к **идентификаторам** топиков. В значениях метаключей (`title`, `description` и т. п.) допускаются стандартные символы соответствующего метаключа.

Для метаключа `units` используется машинная форма по словарю [Wiren Board MQTT Conventions §3 «Control Types»](https://github.com/wirenboard/conventions#3-control-types); драйвер и UI отображают её в человеческой форме. Например: `deg C` → `°C`, `m^3` → `m³`, `μg/m^3` → `μg/m³`.

### 2.2 Стиль snake_case

Идентификатор формируется из смысловых слов, разделённых одним символом `_`. Каждое слово состоит из строчных букв и/или цифр.

Идентификатор не должен начинаться или заканчиваться символом `_` и не должен содержать подряд два и более символа `_`.

**Примеры допустимых идентификаторов** (формы по канону §3-§6):

- `uptime` — служебный идентификатор-исключение (§3.4);
- `t_mcu` — короткий префикс + сущность;
- `u_rms_l1` — короткий префикс + модификатор + сущность;
- `count_single_1` — длинный префикс + модификатор + сущность (этикетка клеммы);
- `cmd_reset_counters` — команда (§6.3).

**Примеры запрещённых идентификаторов:**

| Идентификатор | Нарушение |
| --- | --- |
| `Temperature` | заглавная буква |
| `_temperature` | `_` в начале |
| `temperature_` | `_` в конце |
| `temperature__1` | двойной `_` |
| `temp-1` | дефис |
| `temp.1` | точка |
| `temp 1` | пробел |
| `температура` | кириллица |

### 2.3 Длина

**Жёсткое ограничение:** длина идентификатора не должна превышать 64 символа.

**Рекомендация:** не более четырёх смысловых единиц — слов и/или числовых индексов, разделённых символами `_` — ради читаемости (согласуется с Conventions §1.2). Индексные токены (`ch1`, `ct1`, `l1`, `in1`) считаются одной смысловой единицей каждый. Отдельные канонические имена (§6) могут превышать рекомендацию, если этого требует однозначность.

Под смысловой единицей понимается одно слово или одно число между соседними `_` (или между границами идентификатора).

**Примеры подсчёта смысловых единиц** (формы по канону §3-§6):

| Идентификатор | Единицы | Подсчёт |
| --- | --- | --- |
| `uptime` | 1 | `uptime` |
| `t_mcu` | 2 | `t`, `mcu` |
| `u_rms_l1` | 3 | `u`, `rms`, `l1` |
| `e_ap_ch1_ct1` | 4 | `e`, `ap`, `ch1`, `ct1` |
| `min_supply_voltage_since_startup` | 5 — сверх рекомендации | `min`, `supply`, `voltage`, `since`, `startup` |

Последняя строка превышает рекомендацию §2.3: тот же канал по канону §6.1 — `v_min_vin` (3 единицы).

### 2.4 Особое написание

Аббревиатуры, химические формулы и иные обозначения, имеющие в UI особое написание (со специальными символами или с использованием заглавных букв), в идентификаторе записываются строчными буквами без специальных символов.

Единицы измерения в идентификаторе не указываются — для этого служит метаключ `units`.

**Канонические соответствия для названий веществ, аббревиатур и показателей:**

| В UI | В идентификаторе |
| --- | --- |
| `CO₂` | `co2` |
| `H₂O` | `h2o` |
| `pH` | `ph` |
| `VOC` | `voc` |
| `PM2.5` | `pm25` |
| `PM10` | `pm10` |

### 2.5 Запрещённые сочетания

В идентификаторе не должны встречаться:

- две или более последовательные `_`;
- символ `_` в первой или последней позиции;
- идентификаторы, состоящие только из цифр и `_`.

Идентификатор должен начинаться с буквы латиницы `a-z`.

Каноническое регулярное выражение валидного идентификатора:

```
^[a-z][a-z0-9]*(_[a-z0-9]+)*$
```

## 3. Каноническая схема именования каналов

Имена каналов (компонент топика после `/controls/`) формируются по схеме:

```
<префикс_величины>_[модификатор_]<сущность>
```

- **префикс величины** — обозначение измеряемой физической или дискретной величины (см. §3.1);
- **модификатор** (опционально) — уточнение (`min`/`max`, направление энергии, вид нажатия и т. п., см. §4);
- **сущность** — что/где измеряется (см. §5).

Канонические имена для конкретных классов измерений приведены в §6.

### 3.1 Канонический словарь префиксов

#### 3.1.1 Короткие — стандартные обозначения

Для общеизвестных инженерных величин — однобуквенные или короткие префиксы, совпадающие с символами IEC.

| Префикс | Величина | Типичные `units` |
| --- | --- | --- |
| `u_` | напряжение сети (AC mains, ~220В/380В, 50 Гц) | `V` |
| `v_` | низковольтное напряжение (DC, питание МК, плат, батарей) | `V`, `mV` |
| `i_` | ток | `A`, `mA` |
| `f_` | частота | `Hz` |
| `p_` | активная мощность | `W`, `kW` |
| `q_` | реактивная мощность | `var`, `kvar` |
| `s_` | полная мощность | `VA`, `kVA` |
| `e_` | энергия | `Wh`, `kWh`, `kvarh` |
| `t_` | температура | `deg C`, `deg F` |
| `pf_` | коэффициент мощности | — |
| `thd_` | THD | `%` |
| `co2_` | концентрация CO₂ | `ppm` |
| `pm25_`, `pm10_`, `pm1_` | взвешенные частицы | `μg/m^3` |
| `voc_` | летучие органические | `ppm`, `ppb` |
| `cmd_` | команда (write-only) | — |
| `di_` | дискретный вход (по этикетке клеммы, см. §3.2) | — |
| `do_` | дискретный выход / реле (по этикетке клеммы) | — |
| `ai_` | аналоговый вход (по этикетке клеммы) | зависит от режима |
| `ao_` | аналоговый выход (по этикетке клеммы) | зависит от режима |

#### 3.1.2 Длинные — при отсутствии общепринятой короткой формы или при конфликте

| Префикс | Величина | Типичные `units` |
| --- | --- | --- |
| `time_` | длительность | `s`, `h`, `min` |
| `pressure_` | давление | `bar`, `Pa` |
| `volume_` | объём | `m^3`, `l` |
| `concentration_` | концентрация (общая) | `ppm`, `mg/m^3` |
| `count_` | счётчик событий | — |
| `state_` | дискретное состояние (без клеммы) | — |
| `alarm_` | аварийный флаг | — |
| `level_` | уровень (заряд, шум, жидкость) | `%`, `m`, `dB` |
| `humidity_` | влажность | `%` |
| `illuminance_` | освещённость | `lx` |
| `sound_level_` | уровень звука | `dB` |
| `flow_` | расход | `m^3/h`, `l/min` |
| `speed_` | скорость | `m/s`, `rpm` |
| `angle_` | угол | `deg` |
| `resistance_` | сопротивление | `Ohm` |
| `setpoint_` | целевое значение (уставка) для регулирования; составной: `setpoint_<величина>_<сущность>` (например, `setpoint_t_ambient`, `setpoint_humidity_ambient`, `setpoint_pressure_l1`) | по единице регулируемой величины |

#### 3.1.3 Разведение конфликтов однобуквенных префиксов

| Короткий | Длинный (используется длинный) |
| --- | --- |
| `u_` (сетевое напряжение AC) и `v_` (низковольтное DC) — оба используются раздельно | — |
| `t_` (температура) — используется | `time_` (время) — длинный, чтобы отличить от `t_` |
| `p_` (активная мощность) — используется | `pressure_` (давление) — длинный |
| `i_` (ток) — используется | `illuminance_` (освещённость) — длинный |
| `s_` (полная мощность) — используется | `speed_`, `sound_level_`, `state_`, `setpoint_` — длинные |
| `c_` — **не используется** (был бы конфликт count/co2/concentration) | `count_`, `co2_`, `concentration_` — каждое полное |
| `v_` (низковольтное DC) — используется | `volume_` (объём) — длинный |

Префиксы парсятся как литеральные строки до первого `_`: `t_mcu` → префикс `t`, `time_<сущность>` → префикс `time`. Они не путаются при программном разборе.

**Префикс `set_` не используется.** Для уставок (целевых значений) применяется длинный префикс `setpoint_` (§3.1.2) — он точнее и совпадает с устоявшейся инженерной терминологией. Короткий `set_` неоднозначен: `set_temperature` можно прочитать и как команду «установить температуру», и как «заданную температуру» (значение), — в каноне не закреплён.

### 3.2 Правило для каналов с клеммой на корпусе

Для каналов, привязанных к физической клемме устройства (дискретные/аналоговые входы и выходы), имя формируется как:

```
<префикс_типа>_<этикетка_клеммы>
```

где этикетка клеммы берётся **дословно с этикетки устройства** и приводится к виду:

- весь текст в нижнем регистре;
- пробелы убираются;
- **если этикетка уже начинается с префикса типа** (`DI`, `DO`, `AI`, `AO`) — этот префикс **не дублируется**: остаётся только хвост (например, `DI1` → `di_1`, не `di_di1`).

| Этикетка на устройстве | Имя в шаблоне |
| --- | --- |
| `K1` | `do_k1` |
| `K 1` (с пробелом) | `do_k1` (пробел убран) |
| `K01` (с ведущим нулём) | `do_k01` (ноль сохраняется) |
| `1` (просто номер) | `di_1` |
| `DI1` | `di_1` (префикс не дублируется) |
| `DI 1` | `di_1` |
| `IN1` | `di_in1` |
| `Relay 2` | `do_relay2` |
| `DO5` | `do_5` |
| `AI3` | `ai_3` |
| `AO2` | `ao_2` |
| `K1A` | `do_k1a` (буквенный суффикс склеивается с номером) |

**Имена привязаны к этикетке устройства.** Этот выбор приоритезирует **читаемость** (id канала сопоставляется с надписью на корпусе) над сквозной унификацией: физически одинаковые каналы у разных устройств могут получить разные имена в зависимости от маркировки (`do_k1` vs `do_5` vs `do_relay2`). Это нормально — каждое имя соответствует своей этикетке.

**Пробелы и компоновка этикетки.** Пробелы между всеми элементами этикетки убираются полностью (например, `Relay 2` → `do_relay2`, слово и номер склеиваются в один токен). Разделение через `_` сохраняется только если оно проистекает из правил §3.2 (префикс типа + этикетка).

**Производные каналы клеммы.** У одной клеммы, помимо основного канала (`do_k1`, `di_1`), бывают связанные каналы — счётчики нажатий, таймеры, задержки, режимы. Они именуются по общей схеме §3: **префикс собственной величины + этикетка клеммы как сущность** (не через префикс `do_`/`di_`). Этикетка (тот же токен, что после `do_`/`di_`) помещается в хвост:

| Клемма | Основной канал | Производный канал | Смысл |
| --- | --- | --- | --- |
| вход `1` | `di_1` | `count_single_1` | счётчик одиночных нажатий входа 1 |
| выход `K1` | `do_k1` | `time_k1` | таймер выхода K1 |

Так производный канал соседствует с основным по общей части величины и однозначно привязан к своей клемме.

### 3.3 Оговорка для нестандартных величин

Если измеряемая величина не входит в словарь §3.1 — используется **понятное описательное имя** без специального префикса. Пример (WB-MSW, PIR-сенсор):

| id | Что |
| --- | --- |
| `motion` | Текущее значение PIR-сенсора |
| `motion_max` | Максимум PIR с момента последнего сброса |

При появлении нового семейства устройств с нестандартными измерениями такие имена можно добавлять в словарь после согласования.

**Значения в условных единицах.** Если канал публикует величину в условных или относительных единицах (сырое значение датчика, уровень сигнала, безразмерный показатель — «попугаи»), метаключ `units` не задаётся (или задаётся условная единица). Имя канала при этом строится по общим правилам — по описательной величине (`motion`, `signal_level`), а не по физическому префиксу. Отсутствие `units` — нормальная ситуация для таких каналов, а не ошибка.

### 3.4 Часто используемые идентификаторы-исключения

Часть канонических имён не вписывается в общую схему §3 — это короткий канонический набор устоявшихся имён, применяемых во всех WB-шаблонах:

| id | Назначение |
| --- | --- |
| `sn` | Серийный номер устройства |
| `fw` | Версия прошивки |
| `uptime` | Время с момента включения |
| `hw_batch` | Номер партии оборудования |
| `frequency` | Частота сети (когда нет привязки к фазе) |

Эти имена закреплены каноном §6 и расширяются только по согласованию. Идентификаторы данного класса:

- не имеют префикса из §3.1 (либо префикс есть в §3.1, но употребляется полное слово, если у канала единственная очевидная величина — как у `frequency` при префиксе `f_`);
- не имеют сущности из §5;
- не выводятся по общей схеме §3;
- по-прежнему обязаны удовлетворять §2 (алфавит, snake_case, длина, regex).

**Единственная очевидная величина → полное слово.** Если величина у устройства измеряется единожды и её смысл очевиден без сущности, используется полное слово величины без префикса и без сущности: `frequency` (частота сети), `temperature`, `humidity` (климатический датчик, см. §6.4). Как только та же величина распределяется по фазам, каналам или входам — применяется регулярная схема §3 с префиксом: `f_l<N>` (частота по фазам), `t_mcu` (температура МК). То есть полное слово — это форма для единственного экземпляра, префикс+сущность — для нескольких.

### 3.5 Многоканальные устройства

Для устройств с несколькими измерительными каналами (MAP-серия и т. п.) номер канала — это **сущность `ch<K>` в хвосте** имени (по общей схеме §3), а не префикс. Дискриминатор канала стоит в конце, как у прочих связанных каналов (§3.6).

Физический вход в имени зависит от величины:

- **напряжение сети** — общее для устройства, адресуется фазой `l<N>`, без `ch`: `u_rms_l1`, `angle_u_l1`, `frequency` (см. §6.2.1);
- **ток и производные от него** (мощность, энергия, коэффициент мощности, THD тока) — по каналу и трансформатору тока: `ch<K>` + `ct<N>`.

```
<префикс_величины>_[модификатор_]ch<K>_ct<N>     (ток и производные)
<префикс_величины>_[модификатор_]ch<K>_total     (итог по каналу)
```

Примеры: `i_rms_ch1_ct1`, `p_ch1_ct1`, `e_ap_ch3_ct2`, `e_ap_ch1_total`.

### 3.6 Группировка связанных каналов

При выборе имён для группы связанных каналов общая часть помещается в **начало** идентификатора, различающаяся — в **конец**. Связанные каналы тогда соседствуют при алфавитной сортировке в UI и в MQTT-эксплорерах.

Пример (по оговорке §3.3 — нестандартная величина): `vbus_raw_charger` / `vbus_raw_discharger` (общий `vbus_raw_*`); не `charger_vbus_raw` / `discharger_vbus_raw`.

Рекомендация, а не строгое правило: для канонических имён §6 порядок диктуется общей схемой §3 (префикс + модификатор + сущность); правило применимо в случаях, не покрытых каноном. Номер измерительного канала `ch<K>` тоже стоит в хвосте (§3.5), а не в начале.

## 4. Канонический словарь модификаторов

| Модификатор | Применение | Пример |
| --- | --- | --- |
| `min`, `max`, `avg` | статистические | `v_min_vin`, `t_max_mcu` |
| `peak`, `rms` | форма волны (для сетевых `u_*` модификатор `rms` указывается явно) | `u_rms_l1`, `u_peak_l1` |
| `ap`, `an`, `rp`, `rn` | направление энергии: active +/−, reactive +/− | `e_ap_l1`, `e_rn_total` |
| `single`, `long`, `double`, `shortlong` | виды нажатий | `count_single_1`, `count_shortlong_3` |
| `total` | сумма по фазам / каналам (используется и как сущность) | `e_ap_total`, `s_total` |
| `u`, `i`, `p`, `q`, `s` | sub-quantity для составных префиксов (`angle_`, `thd_` и др.): уточняет, к какой электрической величине относится производный канал | `angle_u_l1` (угол **напряжения**), `thd_u_l1` (THD **напряжения**), `thd_i_l1` (THD **тока**) |

## 5. Канонический словарь сущностей

| Сущность | Значение |
| --- | --- |
| `vin` | клеммник входного питания (этикетка «Vin») |
| `mcu` | микроконтроллер |
| `board` | плата |
| `l<N>` | фаза сети по этикетке (`l1`, `l2`, `l3`) |
| `ct<N>` | трансформатор тока (вход тока многоканального счётчика) |
| `ch<K>` | измерительный канал многоканального устройства (`channel` → `ch`) |
| `total` | сумма по фазам / трансформаторам / каналам |
| `ambient` | окружающая среда (для уставок и производных величин; сами каналы климатического датчика — полными словами, §6.4) |

**Оговорка:** если сущность не входит в словарь — используется понятное название (например, по этикетке устройства или по контексту, см. §3.3).

**Каналы клеммы и производные от них.** Префиксы `di_/do_/ai_/ao_` именуют непосредственный канал клеммы (§3.2). Производные каналы (счётчики, таймеры, агрегации) используют **этикетку клеммы как сущность** — тот же токен, что стоит после `di_`/`do_` (см. §3.2, «Производные каналы клеммы»): клемма `di_1` → счётчик `count_single_1`. Имя производного канала следует за маркировкой клеммы.

**Числовые индексы — с 1.** Индексы каналов, входов, фаз, трансформаторов (`ch<K>`, `l<N>`, `ct<N>`, этикетки клемм) нумеруются с **1** и соответствуют маркировке на корпусе; канал 1 не превращается в индекс 0. Не путать с индексом элемента в массиве `enum_titles` — тот отсчитывается с 0 как обычный индекс массива (см. WB-STD-003 §4.3).

## 6. Канонические имена

Раздел содержит канон имён для каналов, многократно встречающихся в шаблонах WB. Применяется ко всем новым шаблонам.

**Канон не исчерпывающий.** Любая корректная комбинация «префикс из §3.1 + (опц.) модификатор из §4 + сущность из §5 (или произвольная по оговорке)» является валидным именем — даже если в таблицах §6.1-§6.5 такой строки нет. Например, по аналогии с `pm25` (§6.4) равно допустимы `pm10`, `pm1`. Таблицы §6 показывают типичные сочетания, а не все возможные.

Существующие имена в legacy-шаблонах сохраняются для совместимости — миграция определяется отдельным планом.

### 6.1 Служебные каналы

Каналы устройств Wiren Board, общие для большинства семейств; обычно размещаются в группе `g_hw_info` (см. WB-STD-003 «Шаблоны serial устройств», Приложение А).

Идентификаторы `sn`, `fw`, `uptime`, `hw_batch` — устойчивые исключения из схемы §3 (см. §3.4).

| `id` | `name` (EN) | RU перевод | `units` | Назначение |
| --- | --- | --- | --- | --- |
| `sn` | Serial Number | Серийный номер | — | Серийный номер устройства |
| `fw` | Firmware Version | Версия прошивки | — | Версия прошивки |
| `uptime` | Uptime | Время работы с момента включения | `s` | Время с включения |
| `hw_batch` | HW Batch Number | Номер партии | — | Номер партии аппаратуры |
| `t_mcu` | MCU Temperature | Температура МК | `deg C` | Температура микроконтроллера |
| `v_mcu` | MCU Voltage | Напряжение питания МК | `V` | Напряжение питания микроконтроллера |
| `v_vin` | Supply Voltage | Напряжение питания | `V` | Напряжение питания устройства (клеммник Vin) |
| `v_input` | Input Voltage | Входное напряжение | `V` | Для устройств UPS, преобразователей |
| `v_min_vin` | Min Supply Voltage Since Startup | Мин. напряжение питания с момента включения | `V` | Минимум за время работы |
| `v_min_mcu` | Min MCU Voltage Since Startup | Мин. напряжение МК с момента включения | `V` | Минимум за время работы |
| `t_max_mcu` | Max MCU Temperature Since Startup | Макс. температура МК с момента включения | `deg C` | Максимум за время работы |

### 6.2 Трёхфазные электрические величины

Применяются для счётчиков энергии и измерителей мощности.

#### 6.2.1 Однофазные / трёхфазные счётчики

| `id` | `name` (EN) | RU перевод | `units` |
| --- | --- | --- | --- |
| `frequency` | Frequency | Частота сети | `Hz` |
| `u_rms_l<N>` | U RMS L*N* | Напряжение фазы *N* | `V` |
| `i_rms_l<N>` | I RMS L*N* | Ток фазы *N* | `A` |
| `p_l<N>` | P L*N* | Активная мощность фазы *N* | `W` |
| `q_l<N>` | Q L*N* | Реактивная мощность фазы *N* | `var` |
| `s_l<N>` | S L*N* | Полная мощность фазы *N* | `VA` |
| `pf_l<N>` | PF L*N* | Коэффициент мощности фазы *N* | — |
| `angle_u_l<N>` | U Angle L*N* | Угол напряжения фазы *N* | `deg` |
| `e_ap_l<N>` | E AP L*N* | Активная энергия (+) фазы *N* | `kWh` |
| `e_an_l<N>` | E AN L*N* | Активная энергия (−) фазы *N* | `kWh` |
| `e_rp_l<N>` | E RP L*N* | Реактивная энергия (+) фазы *N* | `kvarh` |
| `e_rn_l<N>` | E RN L*N* | Реактивная энергия (−) фазы *N* | `kvarh` |
| `thd_u_l<N>` | U THD L*N* | THD напряжения фазы *N* | `%` |
| `thd_i_l<N>` | I THD L*N* | THD тока фазы *N* | `%` |

`<N>` — номер фазы (`1`, `2`, `3`). Для итогов по всем фазам используется сущность `total` (например, `e_ap_total`).

> **`frequency` vs `f_l<N>`.** Голое слово `frequency` — исключение по §3.4: используется, когда измерение частоты единственное и привязано к сети в целом (без фазы). Если счётчик меряет частоту по фазам — каноническая форма по §3: `f_l<N>` (и `f_total` для итоговой).

#### 6.2.2 Многоканальные счётчики (MAP-серия)

Счётчик измеряет несколько токовых каналов (`ch<K>`) через трансформаторы тока (`ct<N>`) при одном общем измерении сетевого напряжения. Соответственно:

**Напряжение — общее, без канала** (адресуется фазой, см. §6.2.1): `u_rms_l<N>`, `angle_u_l<N>`, `thd_u_l<N>`, `frequency`.

**Ток и производные — по каналу и трансформатору** (`ch<K>` + `ct<N>` в хвосте):

| `id` | Пример | Назначение |
| --- | --- | --- |
| `i_rms_ch<K>_ct<N>` | `i_rms_ch1_ct1` | Ток канала *K*, трансформатор *N* |
| `p_ch<K>_ct<N>` | `p_ch1_ct1` | Активная мощность |
| `q_ch<K>_ct<N>` | `q_ch1_ct1` | Реактивная мощность |
| `s_ch<K>_ct<N>` | `s_ch1_ct1` | Полная мощность |
| `pf_ch<K>_ct<N>` | `pf_ch1_ct1` | Коэффициент мощности |
| `thd_i_ch<K>_ct<N>` | `thd_i_ch1_ct1` | THD тока |
| `e_ap_ch<K>_ct<N>` | `e_ap_ch4_ct3` | Активная энергия (+); аналогично `e_an_`, `e_rp_`, `e_rn_` |
| `e_ap_ch<K>_total` | `e_ap_ch1_total` | Итог активной энергии по каналу *K* |

`<K>` — номер канала (`1`-`12` для MAP12). `<N>` — номер трансформатора тока в канале. Оба индекса — с 1 (§5).

> Дискриминаторы `ch<K>` и `ct<N>` стоят в хвосте по общей схеме §3, не ведущим префиксом.

### 6.3 Дискретные и аналоговые входы и выходы, счётчики

Для каналов, привязанных к клемме, используется правило `<префикс_типа>_<этикетка_клеммы>` (§3.2).

| `id` | `name` (EN) | RU перевод | Назначение |
| --- | --- | --- | --- |
| `di_<этикетка>` | Input *N* | Вход *N* | Текущее состояние дискретного входа |
| `do_<этикетка>` | K *N* / Relay *N* | K *N* / Реле *N* | Релейный/дискретный выход |
| `ai_<этикетка>` | AI *N* | Аналоговый вход *N* | Аналоговый вход; единицы по `units` |
| `ao_<этикетка>` | AO *N* | Аналоговый выход *N* | Аналоговый выход; единицы по `units` |

**Счётчики нажатий** (для входов, поддерживающих распознавание нажатий):

`<этикетка>` — этикетка клеммы входа (тот же токен, что после `di_`; §3.2). Для входа с этикеткой `1` (канал `di_1`):

| `id` | `name` (EN) | RU перевод |
| --- | --- | --- |
| `count_<этикетка>` | Input N Counter | Вход N: счетчик замыканий |
| `count_single_<этикетка>` | Input N Single Press Counter | Вход N: счетчик одиночных нажатий |
| `count_long_<этикетка>` | Input N Long Press Counter | Вход N: счетчик длинных нажатий |
| `count_double_<этикетка>` | Input N Double Press Counter | Вход N: счетчик двойных нажатий |
| `count_shortlong_<этикетка>` | Input N Shortlong Press Counter | Вход N: счетчик коротких, а затем длинных нажатий |
| `cmd_reset_counters` | Reset All Counters | Сбросить все счетчики |

Пример для входа `1`: `count_1`, `count_single_1`, `count_long_1`, `count_double_1`, `count_shortlong_1`.

**Примечания:**

- Употребляется «Single», не «Short» — по противопоставлению с «Long» и «Double».
- «Shortlong» пишется слитно (в `id` и в `title`).
- Счётчики имеют `reg_type: "press_counter"`, `sporadic: true`.
- Счётчик — производный канал клеммы: сущность = этикетка клеммы входа, тот же токен, что в `di_<этикетка>` (§3.2, §5). Клемма `di_1` → счётчик `count_single_1`.
- Для команд (`cmd_*`) рекомендуется форма `cmd_<глагол>_<объект>` (например, `cmd_reset_counters`). Это рекомендация, а не строгое правило: за `cmd_` может следовать и другой формат, если глагол-фраза в него не укладывается.

### 6.4 Климатические каналы (WB-MSW и аналоги)

У климатического датчика каждая величина измеряется единожды, поэтому имя — полное слово величины без сущности (принцип §3.4 «единственная очевидная величина → полное слово»). Суффикс `_ambient` не используется.

| `id` | `name` (EN) | RU перевод | `units` |
| --- | --- | --- | --- |
| `temperature` | Temperature | Температура воздуха | `deg C` |
| `humidity` | Humidity | Влажность воздуха | `%` |
| `co2` | CO₂ | Концентрация CO₂ | `ppm` |
| `illuminance` | Illuminance | Освещённость | `lx` |
| `sound_level` | Sound Level | Уровень шума | `dB` |
| `pressure` | Atmospheric Pressure | Атмосферное давление | `mbar` |
| `pm25` | PM2.5 | Взвешенные частицы PM2.5 | `μg/m^3` |
| `voc` | VOC | Летучие органические соединения | `ppm` |
| `motion` | Motion | Текущее значение PIR-сенсора | — |
| `motion_max` | Motion Max | Максимум PIR с момента сброса | — |

`motion` / `motion_max` — по оговорке §3.3 (нестандартная величина, условные единицы).

Двоичные сигналы аварии (`1` = тревога активна, `0` = нормально).

| `id` | `name` (EN) | RU перевод | Назначение |
| --- | --- | --- | --- |
| `alarm_overvoltage` | Overvoltage Alarm | Перенапряжение | Превышение допустимого напряжения |
